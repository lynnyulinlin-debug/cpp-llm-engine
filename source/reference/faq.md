# FAQ 常见问题

这个页面只回答主线里最常见、最容易重复出现的问题。

## 1. 编译相关

### 1.1 为什么我本机能跑 `chapter00`，但后面的章节编译失败？

通常是因为主线章节开始引入了更具体的 target、头文件或库依赖。先看报错属于编译器、链接器还是路径问题，再回到对应章节的 `README` 和 `CMakeLists.txt`。

### 1.2 为什么我改了代码，但 `docs:build` 还是报旧错误？

多数情况下是缓存、锚点链接或站点层路径问题。先跑 `npm run docs:check-links`，再确认修改的 markdown 文件是否真的被站点入口映射到，最后检查页面内链接是不是指向了不存在的标题或文件。

## 2. 运行相关

### 2.1 为什么 `chapter00` 能跑，`chapter01` 却不行？

`chapter00` 主要验证环境和最小推理基线，`chapter01` 开始进入权重加载和对象模型。如果 `chapter01` 失败，优先检查模型文件、loader 和 `Tensor` 的 shape / dtype / ownership。

### 2.2 为什么同一章节在 CPU 上能跑，在 GPU 上失败？

这通常表示 CPU 路径和 CUDA 路径的前置条件不同。先确认你当前读的是 CPU-first 路径，还是已经切到 GPU backend，再判断失败点属于环境、构建还是实现。

## 3. 内存相关

### 3.1 为什么生成过程中会越来越占内存？

最常见的原因是 cache、buffer 或中间结果没有按预期复用。先看 `chapter05_generation` 的 `KV Cache`、scheduler 和请求生命周期，再判断是不是把本该复用的状态重新分配了。

### 3.2 为什么量化后还是很占内存？

量化通常先降低权重表示成本，但不一定自动解决激活、cache 或临时 buffer。先看 `chapter06_quantization` 的量化范围，再看是不是该在 `chapter05_generation` 或 `chapter07_benchmark` 里继续优化 runtime。

## 4. 验证相关

### 4.1 为什么我分不清是逻辑错还是 benchmark 噪声？

先把正确性测试和 benchmark 分开。逻辑错先修，benchmark 再看性能；如果两者混在一起，结论通常会不稳定。

### 4.2 回归测试和端到端测试有什么区别？

端到端测试看当前链路是否正确，回归测试看历史问题有没有回来。固定样例应优先进入回归基线，而不是每次都当成新的 e2e 样例。

### 4.3 为什么要先看 `summary.md`？

因为 `summary.md` 先给出本章结论、边界和下一步，比直接翻正文更快定位入口。

## 5. 怎么用这个页面

- 先按问题类别找入口
- 再回到对应章节的 `intro.md` 或 `summary.md`
- 如果仍然不清楚，再看正文和附录里的规则文档

## 6. 维护规则

- 问题尽量短，答案尽量指向具体章节
- 不在 FAQ 里展开长篇原理
- 新增常见问题时，优先补到最接近的主线章节，而不是让 FAQ 变成第二主线
