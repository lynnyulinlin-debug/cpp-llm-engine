# 03.3 CPU Reference Implementation CPU 参考实现

对应代码：见 [本章代码索引](/code/chapter03_matmul)

## 1. 这一页要解决什么

先实现一个正确的 CPU 版本 `MatMul`，作为后续 cuBLAS 版本的对照基线。  
这一页的目标不是最快，而是最容易读懂、最容易验证。

## 2. 读完你应该能做什么

- 理解为什么先做 CPU 参考实现
- 理解如何用朴素实现验证数学正确性
- 理解 correctness baseline 的意义

## 3. 为什么这一步重要

高性能实现之前，必须先确认数学是对的。  
CPU 参考实现通常最直观，也最适合用来定位布局、转置和维度错误。

如果参考实现都不稳定，后面的 cuBLAS 路径就很难判断到底是优化引入了偏差，还是最初的数学定义就已经错了。

## 4. 这页应该怎么写

参考实现要尽量朴素：

- 先检查输入形状
- 再分配输出张量
- 然后用三重循环累加
- 最后返回结果

实现时不要一开始就追求 cache 友好。  
参考实现的任务是成为正确性基线，不是成为最快版本。

最小实现里，形状检查应该直接写出来：

```cpp
assert(A.cols() == B.rows());
Tensor C(A.rows(), B.cols());
```

源码锚点：`code/chapter03_matmul/src/matmul_cpu.cpp`

这样“边界检查”和“核心计算”就会同时出现在代码里，读者也更容易把形状错误和累加错误区分开。

## 5. 为什么朴素实现更适合做基线

朴素三重循环有两个优点：

- 结构和数学定义一致，读者容易理解
- 一旦结果不对，很容易判断是维度顺序错了，还是累加逻辑错了

这也是为什么参考实现通常应该先写得“笨”一点。  
当你需要验证 cuBLAS、转置或者布局映射时，最需要的是一个可以直接对照的小实现，而不是一个高度优化但难读的版本。

## 6. 怎么验证

- 与手工小矩阵结果一致
- 与后续 cuBLAS 结果一致
- 错误维度输入能被正确拒绝

对于小矩阵，最好直接写出手算结果。  
这样一旦数值不对，你可以立刻判断是维度顺序错了，还是累加逻辑错了。

最小伪代码可以写成：

```cpp
for (std::size_t i = 0; i < M; ++i) {
    for (std::size_t j = 0; j < N; ++j) {
        float sum = 0.f;
        for (std::size_t k = 0; k < K; ++k) {
            sum += A[i * K + k] * B[k * N + j];
        }
        C[i * N + j] = sum;
    }
}
```

源码锚点：`code/chapter03_matmul/src/matmul_cpu.cpp`

这段循环的价值在于可读性，而不是性能。

## 7. 常见问题

- 维度顺序搞反
- 累加顺序错误
- 为了“快”过早优化，破坏正确性
