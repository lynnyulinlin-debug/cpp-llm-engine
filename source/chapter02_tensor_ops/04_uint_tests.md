# 02.4 Unit Tests 单元测试


## 这一页要解决什么

用简单单元测试验证 `reshape` 和 `slice` 的 view 语义是否正确。

## 读完你应该能做什么

- 理解为什么 view 操作必须测试
- 理解如何用最小案例验证共享存储
- 理解测试应该覆盖语义而不只是输出值

## 为什么这一步重要

这一章的正确性不在于“能不能跑”，而在于“有没有保持 view 语义”。如果测试缺失，后面很容易在不知不觉中引入数据复制或偏移错误。

## 测试重点

- `reshape` 不复制数据
- `slice` 返回共享存储
- 切片内容和预期一致
- 元素数和 shape 保持合理

## 建议测试方式

- 固定输入
- 小尺寸张量
- 明确预期结果
- 对共享地址或偏移进行检查

如果测试环境允许，最好同时检查两个层面：

1. 数值层面：切片后的数据内容是否正确
2. 结构层面：新旧张量是否共享同一份 storage，偏移是否如预期变化

## 怎么验证

- 测试能稳定通过
- 错误实现会在测试中失败
- 视图语义被明确约束住

这类测试的意义不是覆盖所有情况，而是把最容易被误写的语义锁住，避免后续重构时把共享存储悄悄改成拷贝。

一个最小测试样例可以写成：

```cpp
TEST(TensorView, ReshapeSharesStorage) {
    Tensor a = Tensor::from_vector<float>("a", {2, 2}, {1, 2, 3, 4});
    Tensor b = reshape(a, {4});
    EXPECT_EQ(a.storage(), b.storage());
    EXPECT_EQ(b.to_vector<float>()[3], 4.f);
}
```

这类测试同时验证了“数据内容”和“共享关系”。

## 常见问题

- 只测数值，不测共享关系
- 只测正向路径，不测边界情况
- 用太大的输入掩盖了语义错误
