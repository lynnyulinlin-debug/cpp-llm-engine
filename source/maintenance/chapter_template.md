# Chapter Template 章节导读模板

这份模板只约束章节 `intro.md`。目标是让学习者在几分钟内知道：先做什么、会得到什么、如何判断成功、下一步为什么顺着来。

章节导读最多保留 4 个二级标题。主图、框架对照、阅读入口和下一章提示都服务于同一条学习顺序，不单独制造多个导航层。

章节正文是稳定知识资产，不绑定某套学习计划。学习计划可以引用本章，但本章不得出现 `Task 1`、`任务 4`、“第一期任务”等计划编号；章节之间只使用技术依赖和章节名称建立关系。

## 1. 本章位置与成功标准

开头先给出本章最小可见结果，不先讲抽象分层。

- 一句话说明本章要解决的问题
- 给出最小命令、测试或输出
- 放本章主图；图注只说明本章位于哪一层
- 用一句话说明本章不做什么

示例：

```md
这一章把单层 decoder 接入生成循环，先让一个请求完成 `prefill -> decode -> output`。

```bash
bash code/chapter05_generation/scripts/run.sh
```

成功标准：测试通过，并看到 request 完成和生成结果。

![本章主图](../assets/diagrams/chapter05-main.svg)

本章不实现 GPU kernel 或完整 HTTP 服务。
```

## 2. 内容地图

用 3 到 5 项说明学习结果。每项必须是“动作 + 对象 + 验证结果”，不要只写“理解”“掌握”。

```md
完成后可以：

- 创建一个 Request，并检查它的状态迁移
- 区分 prefill 和 decode 的输入输出
- 复用 KV Cache，测试重复计算是否减少
- 运行端到端测试，确认输出和资源回收正常
```

框架对照最多放一张三列小表：`本章实现 / 真实框架中的对应物 / 继续阅读`。详细对照先进入 `reference/framework_comparison.md` 和 `reference/ecosystem/README.md`，再下钻到单项目卡，不在 intro 展开第二条主线。

正文使用“问题与产物 -> 算法镜像 -> C++ 实现 -> 验证证据 -> 框架坐标”组织证据。算法镜像按对象选择，不要求每章都有 Python：Attention、Scheduler、量化解码和缓存算法可以使用短伪代码；Loader、Storage/View、Benchmark 和 Profiling 优先使用文件布局、对象图或测量表。

| 证据 | 要求 | 适合形式 |
| --- | --- | --- |
| 问题与产物 | 必需 | 输入输出、命令和成功标准 |
| 算法镜像 | 按需 | 10-30 行 Python 伪代码、状态图或步骤表 |
| C++ 实现 | 必需 | 对象、ownership、backend 和错误契约 |
| 验证证据 | 必需 | CTest、golden、真实 baseline 或 benchmark |
| 框架坐标 | 必需 | intro 小表和 Reference 项目卡链接 |

## 3. 阅读与源码顺序

按实际学习顺序列出 3 到 7 个页面。每页只回答“先看什么、会看到什么、产出是什么”。

```md
| 顺序 | 页面 | 产出 |
| --- | --- | --- |
| 1 | Request 生命周期 | 状态迁移图和状态测试 |
| 2 | KV Cache | cache 写入与复用测试 |
| 3 | 端到端生成 | 可重复运行的生成结果 |
```

源码入口放在表格之后，最多列 3 个文件；前置章节和下一章各保留一个链接即可。

跨目录的正文、代码、主图、公式和验证入口统一登记在 `source/reference/chapter_assets.md`。intro 只保留本章阅读顺序，不复制完整资产清单；`code/chapterXX/README.md` 继续维护目录内文件级资产总览。

## 4. 验证

集中写本章的验证命令和通过标准，不要把验证拆成“产物、检查、边界、收口”多个标题。

- 构建或运行命令
- 测试命令
- 关键输出或数值标准
- 失败时先检查的一个位置

正文页继续展开实现细节；intro 只告诉学习者如何确认自己走对了。

验证末尾用一句 `下一章：` 说明本章产物如何被下一章消费，不再单独建立二级标题。

用一段话回答三个问题：本章留下了什么、下一章消费什么、为什么必须现在进入下一章。

不要重复整章总结，也不要再开“边界说明”“下一步”“复盘路径”等并列标题。

## 标题规则

- `intro.md` 最多 4 个二级标题
- 每个正文页建议 3 到 5 个二级标题
- 三级标题只用于同一实现步骤中的小分支，不用于再次创建导航
- “本章主图”“阅读入口”“框架对照”不单独成为学习目标
- 标题优先写学习者要完成的动作，例如“先让请求跑完”，而不是“运行时边界”

## Checks

- Python 镜像不得成为默认 CMake、CTest 或 `test:regression` 的环境依赖
- 可运行 Python reference 生成的 fixture 必须记录 seed、shape、dtype、容限和来源
- `npm run docs:check-links`
- `npm run docs:check-reference`
- `npm run docs:build`
- `git diff --check`
