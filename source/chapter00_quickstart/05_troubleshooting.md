# 00.5 Troubleshooting 常见问题排查


对应代码：见 [本章代码索引](/code/chapter00_quickstart)

## 这一页要解决什么

整理第一次跑通推理时最常见的问题和处理方式。

## 读完你应该能做什么

- 知道先检查什么，再检查什么
- 知道如何区分环境问题、模型问题和运行参数问题
- 知道什么时候应该退回 CPU 路径做最小验证

## 常见问题

### 1. 找不到模型文件

- 检查 `-m` 参数是否指向正确路径
- 检查文件是否真的下载完成
- 检查当前目录是否和你预期一致

### 2. 编译失败

- 检查编译器版本
- 检查 CMake 配置是否完成
- 检查是否缺少依赖库

### 3. CUDA 相关错误

- 检查驱动是否安装
- 检查 toolkit 是否可用
- 检查是否真的编译了 CUDA 版本

### 4. 显存不足

- 先换更小的模型
- 先走 CPU 路径确认功能正确
- 再回到 GPU 调优参数

### 5. 输出很慢

- 这不一定是错误，先区分 CPU 路径和 GPU 路径
- 小模型或第一次启动可能本来就慢

## 排查顺序

1. 确认文件路径
2. 确认可执行文件存在
3. 确认模型存在
4. 确认编译路径正确
5. 确认 CPU 回退路径可用

这个顺序对应的是“先外层、后内层”的排障思路：先排路径和文件，再排构建，再排运行参数，最后才看 GPU 和性能问题。多数第一次失败都出在最外层。

## 怎么验证

- 能快速定位问题属于哪一层
- 能用 CPU 路径做最小回退验证
- 能避免把所有问题都归因于模型本身

如果你能在十分钟内把问题归类到“环境、编译、下载、运行”之一，这一页的目标就算完成了。
